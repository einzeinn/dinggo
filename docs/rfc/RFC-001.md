# RFC-001: Dokumentasi Wajib Sebelum Perubahan Scope Besar

**Status:** Aktif
**Berlaku untuk:** Semua agent (AI) dan diri sendiri yang mengerjakan project ini

## Latar Belakang

Project ini dikerjakan solo dengan bantuan AI agent (lewat CLI ini sendiri, atau
tool lain). Tanpa aturan eksplisit, ada risiko perubahan besar (arsitektur, dependency
utama, struktur folder, keputusan teknis) dilakukan tanpa jejak alasan — menyulitkan
diri sendiri di masa depan buat ngerti "kenapa dulu diputusin begini".

## Aturan

**Setiap perubahan, update, atau pengerjaan dengan scope yang lumayan besar WAJIB
didokumentasikan terlebih dahulu**, sebelum eksekusi kode dimulai.

### Kriteria "Scope Lumayan Besar"

Termasuk (tidak terbatas pada):
- Menambah/mengganti model atau layer di arsitektur orkestrasi
- Mengubah struktur folder inti (`core/`, `tools/`, `cli/`)
- Menambah dependency utama baru
- Mengubah alur core loop (nalar → plan → confirm → eksekusi)
- Keputusan yang bakal susah di-reverse (misal format data, skema config)

**Tidak termasuk** (boleh langsung eksekusi tanpa dokumentasi baru):
- Bug fix kecil, typo, formatting
- Perubahan 1 file yang scope-nya jelas dan reversible
- Eksperimen di branch/folder terpisah yang belum masuk main flow

### Prosedur

1. Kalau task masuk kriteria "scope besar", agent **berhenti dulu sebelum coding**
2. Tulis ringkas di `07-TechnicalDecisions.md` (format TD-XXX, lihat contoh yang
   sudah ada) ATAU buat RFC baru (`RFC-002.md`, dst) kalau perubahannya cukup besar
   buat butuh pembahasan sendiri
3. Setelah dokumentasi ditulis, baru lanjut ke plan → confirm → eksekusi (mengikuti
   core loop di `02-PRD.md`)
4. Kalau ada, update `12-Changelog.md` setelah eksekusi selesai

### Kenapa Ini Jadi RFC Pertama

Ini task pertama yang ditugaskan ke agent supaya dari awal, pola kerja "dokumentasi
dulu baru eksekusi" langsung tertanam di setiap interaksi berikutnya — bukan
tambahan yang disisipkan belakangan setelah project udah berantakan.

## Contoh Kasus

| Situasi | Wajib Dokumentasi? |
|---|---|
| Ganti model planner dari Qwen3.5-4B ke model lain | Ya — update TD-003 |
| Nambah tool baru (misal `search_web`) di executor | Ya — update 06-Architecture.md + TD baru |
| Fix bug di `file_ops.py` yang salah handle path relatif | Tidak |
| Ubah warna panel di terminal UI | Tidak |
| Ubah struktur folder `tools/` jadi `tools/file/` + `tools/shell/` | Ya — update 06-Architecture.md |
